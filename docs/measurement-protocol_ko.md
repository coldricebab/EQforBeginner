# 측정 프로토콜

이 문서는 이미 구현된 실제 하드웨어 개발자 베타와, 아직 남아 있는 프로덕션
프로토콜을 구분한다. 데스크톱 앱은 호스트 자격을 충족한 CPAL 입력 장치 ID와
48 kHz 구성만 검색하며, 컴퓨터 출력 장치는 열거하지도, 선택하지도, 열지도 않는다.
저장된 입력 장치 ID는 백엔드가 지속성을 보장할 수 없는 환경에서 쓰이는 재검증용
힌트일 뿐이다. 앱은 선택된 네이티브 48 kHz PCM 입력을 열어 지정한 네이티브 채널
하나를 모노로 추출하고, UMIK 캘리브레이션과 좌/우로 분리된 스윕 WAV를 가져오며,
Roon에서 수동으로 시작한 재생을 인식하고, 임펄스 응답/주파수 응답을 디컨볼루션하고
캘리브레이션하며, 원본 증거를 보존하고, 기존 Phase 4 엔진으로 시험 필터를 설계하고,
P0를 재측정하며, 폐루프 게이트를 통과한 뒤에야 최종 minimum-phase 6개 레이트 ZIP을
생성할 수 있다.

앱에는 여전히 출력 재생 기능도 Roon 제어 기능도 없다. 제품에는 `.mdat`을 직접 읽는
기능이 없다. 앱은 인식된 스윕을 dBFS로 계측하며, 캘리브레이션에 Sens Factor가
포함된 경우 가정에 기반한다는 라벨이 붙은 SPL 추정값을 보여준다. 앰프 볼륨을
설정하거나 절대 SPL을 인증할 수는 없다. 음향적 채널 스왑/과도 신호/마이크 이동
테스트, 하드웨어로 검증된 L/R 타이밍, 세션 다시 열기, 프로덕션 하드웨어 검증은
아직 완료되지 않았다.

## 안전과 연결

1. 기존의 모든 컨볼루션/EQ 필터를 반드시 비활성화하고, 활성 신호 경로가 하나뿐인지
   확인하세요.
2. EQforBeginner에서 UMIK-1과 그 신호가 들어오는 네이티브 입력 채널만 검색해
   선택하세요. CoreAudio가 UMIK-1을 2채널 장치로 노출할 수 있으므로 채널 1부터
   시작하세요. 재생 라우팅은 Roon과 실제 오디오 시스템이 담당하며, EQforBeginner는
   절대 출력 장치를 선택하거나 점유하지 않는다.
3. 시리얼이 일치하는 UMIK 캘리브레이션 파일을 불러오고, 48 kHz 지원을 요구하세요.
4. 세션 전체에 걸쳐 앰프 볼륨과 마이크 게인을 고정하세요.
5. 하드웨어 볼륨을 낮게 잡고 시작하여 실시간 스윕 미터를 지켜보세요. 권장 디지털
   범위는 피크 -30 ~ -6 dBFS이다. -48 dBFS까지 내려가는 조용한 캡처는 독립적인
   20 dB 이상 SNR과 나머지 품질 검사를 모두 통과한 경우에만 허용되며, -6 dBFS를
   넘거나 -1 dBFS 이상에서 클리핑되면 실패한다. Sens Factor가 있을 때 65-85 dB
   SPL은 허용 게이트가 아니라 참고용 권고이다. 소리가 불편하게 느껴지면 즉시
   중단하세요. 이 추정값은 운영체제 입력 게인이 0 dB라고 가정하며 캘리브레이션된
   측정기를 대체하지 않는다.

## 실제 측정 개발자 베타

이 절차는 네이티브 Tauri 앱에서만 실행하세요. 브라우저 미리보기로는 마이크를 열 수
없다.

1. **프로젝트 시작**(Start a project)에서 **스테레오 (L/R)**(Stereo (L/R)) 또는
   **2.1 (L/R + 서브 1개)**(2.1 (L/R + one sub))를 명시적으로 선택하고 라이브
   세션을 시작한 뒤, 애플리케이션 데이터 출력 디렉터리를 기록해 두세요. 이 선택은
   `project.json`에 저장되며 해당 세션 안에서는 조용히 변경될 수 없다.
2. **캘리브레이션 및 L/R 기준 스윕**(Calibration and L/R reference sweeps) 단계로
   이동한 다음, 정확한 UMIK 48 kHz 입력과 네이티브 채널을 검색해 선택하세요. 실제로
   처음 열린 장치와 입력 채널은 그 프로젝트에 고정되므로, 세션 도중에 둘 중 하나를
   바꾸지 말고 새 프로젝트를 시작하세요. 채널 1이 완전히 무음이면 새 프로젝트를
   시작해 채널 2를 시도하세요.
3. 시리얼이 일치하는 UMIK TXT 파일을 가져오세요. 파서는
   `frequency_hz correction_db [phase_degrees]` 형식을 받아들이며, 엄격히 증가하는
   점들과 20 Hz-20 kHz 전 구간 커버리지를 요구하고, 파싱된 시리얼과 범위를 표시한다.
   V2는 따옴표로 묶인 miniDSP 제조사 메타데이터를 허용하면서도 형식이 잘못된 숫자
   행은 여전히 거부한다. 임펄스 응답/주파수 응답에는 크기 보정만 적용되며, 위상은
   출처 정보로만 남고 Sens Factor는 가정에 기반한다는 라벨이 붙은 SPL 추정값에만
   사용된다.
4. `assets/sweeps/Sweep_L_20-20k_refR.wav`를 왼쪽으로,
   `assets/sweeps/Sweep_R_20-20k_refR.wav`를 오른쪽으로 가져오세요. 이 파일들은
   48 kHz 기준 파일로, 지배적인 측정 스윕과 그보다 에너지가 낮은 타이밍 마커를 담고
   있다. 수정된 Tauri IPC는 파일의 원시 `ArrayBuffer`와, 크기가 제한되고 검증된 JSON
   바이트 배열 대체 경로를 모두 받아들인다. 예전의 "raw WAV byte payload" 오류는
   정상적인 결과가 아니다. 업로드한 뒤에는 메인 스윕, 시작 신호, 종료 신호에 대해
   표시된 채널 분석을 확인하세요. 번들로 제공되는 `*_refR.wav` 픽스처는 메인 측정
   스윕이 각각 L 또는 R이더라도 두 마커는 모두 R에 담고 있다.
5. 두 WAV를 모두 Roon에 추가하세요. 그룹으로 묶이지 않은 Zone 하나만 사용하세요.
   Crossfade, Volume Leveling, Radio/셔플/반복을 끄고 대기열을 비우세요. 기준
   측정에서는 MUSE Convolution, PEQ, 샘플레이트 변환을 끄고 Signal Path에서 48 kHz를
   확인하세요. Volume Leveling은 2.1 분리 캡처에서 이중으로 위험하다. 스윕 파일마다
   서로 다른 LUFS 게인을 적용해, 크로스오버 비교가 의존하는 메인 대 서브 상대 레벨을
   조용히 망가뜨릴 수 있다. 앱은 모든 분리 캡처에서 타이밍 마커의 RMS를 교차
   검사하며, 편차가 0.3 dB를 넘으면 탐색을 거부한다.
6. 파이프라인 순서와 체인 불변식(2.1): 크로스오버 탐색(분리 캡처)을 반드시 먼저
   끝내고 그 승자를 하드웨어에 확정한 **뒤에야** 다중 청취 위치 기준 캡처를
   진행한다. 그리고 모든 기준/검증 스윕은 전체 체인 측정이다. 즉 L 스윕을 재생하면
   L 메인과 베이스 매니지먼트된 서브가 함께 구동된다. 컨볼루션 필터는 베이스
   매니지먼트보다 앞단에 있고 크로스오버 아래 대역에서 보정이 L과 R에 동일하게
   적용되므로, 보정 필터를 추가해도 탐색에서 선택한 메인/서브 정렬은 바뀌지 않는다.
   확정된 크로스오버, 딜레이, 극성, 서브 레벨을 나중에 바꾸면 모든 기준 측정과 검증
   측정이 무효가 되므로(앱은 해당 측정들을 폐기하는 방식으로 이를 강제한다) 2.1
   설정을 먼저 고정하도록 계획하세요.
7. 2.1 프로젝트에서는 Raw 캡처 전에 **2.1 서브 통합 설정**(2.1 sub integration
   settings)을 완료하세요. 하드웨어가 실제로 적용할 수 있는 크로스오버 값을
   오름차순으로 2–12개 입력하고(권장 세션 크기는 3–5개이다. 후보 하나마다 스윕 3회가
   필요하므로 후보가 12개면 마이크 한 위치에서 36회를 캡처해야 한다), 모든 분리 측정
   동안 유지되는 메인 기준 딜레이, 0/180도 극성, 서브 레벨도 함께 입력하세요.
   크로스오버가 하나뿐인 계획은 크로스오버 선호도를 식별할 수 없으므로 앱이 거부한다.
   또한 업로드한 두 스윕 WAV가 동일하게 고정된 L 또는 R 기준 스피커에 시작/종료
   마커를 담고 있어야 한다.

   딜레이의 최소, 최대, 스텝은 **앰프가 할 수 있는 범위**를 뜻하며, 탐색할 범위를
   뜻하지 않는다. 탐색은 서브가 실제로 도달하는 지점을 측정한 뒤 그 지점을 기준으로
   크로스오버 반주기만큼 양쪽을 스텝에 맞춰 살펴본다. 따라서 범위를 넓혀도 후보가
   늘지 않으며, 그 창이 잘리는 것만 막아 준다. 기본값은 -10 ms, +25 ms, 0.1 ms이다.
   음수 최솟값이 있어야 "딜레이를 서브우퍼 쪽에 거는" 선택지가 아예 도달 가능해지고,
   +25 ms는 DSP 서브우퍼의 처리 지연에 배치 오프셋까지 포함하며(이전의 5 ms 상한은
   80 Hz에서 반주기에도 미치지 못했다), 0.1 ms는 실제 앰프에서 설정할 수 있는
   스텝이다. 특정 앰프의 한계에 맞춰야 할 때만 범위를 좁히세요. 창이 잘리면 결과는
   조용히 덜 탐색하는 대신 `range_limited`로 보고한다.
   P0에서 모든 크로스오버 값마다 L 메인 단독, R 메인 단독, 서브 단독 캡처를
   수행하세요:

   - 스피커 케이블을 분리하거나 다시 연결하기 전에 반드시 앰프 전원을 끄고
     기다리세요. 절대 전원이 켜진 앰프 출력을 만지지 않는다.
   - 메인 단독 캡처에서는 서브 경로를 비활성화하거나 분리하세요. 반대쪽 메인은
     스윕 대역 밖의 타이밍 마커만 내보내므로 연결된 채로 두어도 된다.
   - 서브 단독 캡처에서는 고정된 타이밍 기준 스피커의 반대쪽 채널을 재생하세요.
     마커를 위해 고정 기준 메인은 연결된 채로 두고, 재생하는 채널의 메인만
     분리하세요. 번들로 제공되는 `*_refR.wav` 파일을 쓰는 경우 L WAV를 재생하고
     R 메인을 마커 스피커로 유지하세요.
   - 세 번의 캡처로 이루어진 모든 묶음에서 동일한 측정 딜레이, 극성, 서브 레벨,
     앰프 볼륨, 마이크 게인, P0 마이크 위치를 그대로 유지하세요.

   그다음 앱은 Phase 3 스코어러를 재사용해 물리적으로 측정된 크로스오버 상태와,
   합성한 메인 딜레이 및 0/180도 극성 대안들의 순위를 매긴다. 측정되지 않은
   크로스오버 필터를 합성하지 않으며, 서브 레벨은 탐색하지 않는다. 표시된 권장값을
   수동으로 적용하고 확정하세요. 이어지는 Raw P0 L+Sub/R+Sub 캡처는 선택적인 마무리
   작업이 아니라 반드시 필요한 결합 경로 증거이다. 스테레오 프로젝트는 이 단계를
   건너뛴다.
8. 크로스오버, 딜레이, 극성/위상, 서브 레벨, 앰프 볼륨, 마이크 게인을 그대로
   유지하세요. 마이크는 동일한 90도 방향으로 세워 둔 상태를 유지하세요.
   2.1에서는 L 또는 R을 재생할 때마다 평소의 베이스 매니지먼트 서브 경로를 계속 활성
   상태로 두어야 하며, 그래야 캡처가 메인 단독 응답이 아니라 L+Sub와 R+Sub를
   나타낸다.
   표의 각 칸마다 **스윕 측정 대기**(Wait for sweep measurement)를 누르고 해당 WAV를
   처음부터 한 번 재생하세요. 마법사는 먼저 시작 신호를 확인하고, 다음으로 메인 스윕
   레벨을 표시한 뒤, 종료 신호를 확인한다. 완전한 종료 신호가 포함된 첫 모니터
   폴링에서 곧바로 멈추고 저장하며, 고정된 추가 대기 시간은 없다. 제공된 WAV의 공백
   구간과 종료 마커가 이미 필요한 룸 임펄스 응답 꼬리를 확보해 준다. 재생이 정상적으로
   끝난 뒤에는 **측정 취소**(Cancel measurement)를 누르지 마세요. 그 동작은 캡처를
   폐기한다. 두 마커 중 하나라도 끝내 확인되지 않으면 취소하고 WAV의 정확한 처음부터
   다시 시도하세요. 마법사의 다이어그램을 따르세요. P1은 P0에서 왼쪽으로
   25-30 cm, P2는 오른쪽으로 25-30 cm, P3은 스피커 쪽으로 20-25 cm, P4는 P0 뒤로
   20-25 cm, P5는 P0 바로 위로 10-15 cm, P6은 P0에서 뒤-왼쪽 대각선 방향으로
   25-30 cm, P7은 P0에서 뒤-오른쪽 대각선 방향으로 25-30 cm, P8은 P0 바로 아래로
   10-15 cm이다. 먼저 P0 L/R을 측정하고, 되도록 P1-P8을
   측정한 다음, 원래 청취 중심 부근으로 대략 돌아와 P0_END L/R을 측정하세요. 지그
   수준의 정확한 재현은 필요하지 않다. 스윕 소리가 예상보다 크면 즉시 중단하세요.
   중앙 쌍이 모두 있는 경우, 어느 한 채널이라도 200-500 Hz 중앙값 레벨에서 1.0 dB를
   넘게 변하거나 레벨을 제거한 20-500 Hz 형상 RMSE에서 6.0 dB를 넘게 변하면 설계가
   차단된다. 형상 기준은 경로나 위치가 크게 달라진 경우만 잡아낸다.
9. 승인(accepted)으로 표시된 칸만 남기세요. 앱은 이후 인식/디컨볼루션이 실패해도
   원본 모노 WAV를 저장한다. 승인된 측정에는 스윕/캘리브레이션 해시, 임펄스 응답/주파수
   응답, 지표, 알고리즘 버전, 이슈 코드가 담긴 JSON 스냅샷도 함께 저장된다. 완전하게
   승인된 L/R 측정 위치 쌍만 설계에 사용된다.
10. B&K 스타일 또는 Harman 스타일 타깃 커브를 고르거나, 한 줄에
   `frequency_hz level_db` 쌍이 하나씩 들어 있는 사용자 정의 TXT 타깃을 가져온 뒤
   48 kHz 시험 필터를 생성하세요. 사용자 정의 파일은 줄 번호가 표시되는 오류와 함께
   파싱되어 프로젝트에 저장되고 200-500 Hz 구간에서 정렬된다. P0 단독도 허용되지만
   공간적 과적합 경고가 표시되며 부스트를 승인할 수 없다.
   측정 위치가 둘 이상이면, 가중된 위치들에서 반복적으로 나타나는 넓고 얕은 부족분만
   +3 dB를 상한으로 양의 보정을 받을 수 있다. 깊고 좁은 딥은 보호된 딥으로 남는다.
   2.1 프로젝트에서는 이 단계가 5단계이다.
   이 시험 필터는 예측 전용이다. **시험 ZIP 다운로드**(Download trial ZIP)를 클릭하고
   로컬 저장 위치를 지정하세요. 이 작업은 생성된 48 kHz 스테레오 WAV를 Roon용으로
   패키징할 뿐이며 검증으로 인정되지 않는다.
11. Roon의 기존 컨볼루션을 모두 비활성화하고, 방금 생성된 시험 ZIP만 로드하세요.
   그것이 활성 상태인지 확인하고, 모든 하드웨어/볼륨/게인 설정을 고정한 채로 선언
   체크박스에 체크한 다음, 새 검증용 P0 L/R 스윕을 캡처하세요. 이 선언과 정확한 시험
   필터 해시는 저장되지만, 앱이 Roon 존을 독립적으로 확인할 수는 없다.
12. 폐루프 검증을 실행하세요. 두 채널 모두 기존 타깃/피크 게이트를 통과해야 하며,
   수치 예측과의 RMSE가 3.0 dB 이내로 유지되어야 한다. 실패하면 내보내기는 계속
   비활성 상태로 남는다. 시험 파일을 복사하는 식으로 우회하지 마세요.
13. 검증을 통과하면 최종 내보내기를 생성하세요. 앱은 6개 네이티브 레이트를 다시
    설계하고, 최종 48 kHz 구성원을 검증된 시험 필터에 0.05 dB/0.02 ms로 응답
    바인딩하며, ZIP을 검증하고, 그 SHA-256/프로젝트 JSON을 기록하고, 등록된 스윕의
    트루 피크 증가량과 FIR L1 최악 샘플 한계 중 더 큰 값에 1 dB를 더한 권장 헤드룸을
    보고한다.
    최종 단계는 내보내기 전후로 측정 결과 대시보드를 보여준다. 20-500 Hz 및 전대역
    Raw/Target/Predicted/Verified 주파수 응답, 정확한 L/R 타깃 RMSE,
    1/12 옥타브 스무딩된 예측 대 검증 RMSE(스무딩하지 않은 진단값 포함), 필터
    컷/부스트와 보호된 딥 상태, 측정 위치 개수, 헤드룸이 표시된다. Raw/Predicted는
    다중 지점 에너지 평균이며, Verified는 필터를 적용해 새로 측정한 P0이다. 7단계의
    Raw/Predicted/Verified 표시 커브는 가독성을 위해 1/12 옥타브 가우시안 스무딩을
    사용하지만, Target은 정확한 값 그대로이고 수치 게이트도 변하지 않는다.
    **최종 ZIP 다운로드**(Download final ZIP)를 클릭하고 로컬 저장 위치를 지정하세요.
    앱은 정확히 6개 레이트로 구성된 패키지를 다시 검증하고 저장된 바이트를 확인한 뒤
    성공을 보고한다. Roon에는 반드시 이 최종 패키지 ZIP만 로드하고, 보고된 헤드룸을
    적용하고, 클리핑 표시기를 켜고, 표시기가 빨간색으로 바뀌면 레벨을 더 낮추세요.

완료된 라이브 세션 전체는 개발자 베타 수준의 증거이다. 마이크 권한, 실제 채널 정체,
Roon 가져오기, 청감상의 동작, 클리핑 없음은 여전히 사람이 직접 확인해야 한다. 한 번
성공적으로 실행했다고 해서 L/R 딜레이 보정이 승인되는 것은 아니다.

## 레거시 격리 무선 인식기

예전의 전역 **고급 설정**(Advanced settings) 페이지는 제품 UI에서 제거되었다. 그 안에
있던 범위가 제한된 격리 인식기는 소스 코드와 회귀 테스트에 남아 있지만 지원되는 사용자
워크플로가 아니며, 현재 마법사의 어떤 컨트롤도 이를 호출하지 않는다. 전체 라이브 측정
경로가 제품의 유일한 측정 수단이다.

## 캡처 순서

1. 평소의 베이스 매니지먼트 경로를 통해 P0 중앙에서 L과 R을 각각 따로 캡처하세요.
2. P0 응답 증거를 반복해서 확보하고, 레벨이나 응답 형상이 불안정하면 폐기하세요.
   현재 라이브 게이트는 도달 타이밍을 검증하지 않는다.
3. 화면의 배치 안내를 따라 청취 영역 주변에서 P1-P8을 캡처하세요.
4. 접근할 수 없는 측정 위치는 건너뛰어도 되지만, 절대 데이터를 지어내거나 좌우로
   복사하지 않는다.
5. 마지막에 P0를 다시 캡처하세요. 자동 게이트는 레벨이나 응답 형상이 과도하게 변한
   경우를 무효 처리하며, 타이밍을 비롯해 경로 변화가 의심되는 부분은 사람이 확인해야
   한다.

P0는 가중치 2이고, 남겨진 주변 측정 위치는 각각 가중치 1이다. P0_END가 있으면 중앙이
이중으로 계산되지 않도록 P0와 P0_END에 각각 가중치 1을 준다. 단일 지점 프로젝트도
과적합 경고와 함께 예측 전용 시험 필터를 만들 수 있으나, 별도의 승인된 검증 P0 L/R과
라이브 폐루프 게이트를 통과한 뒤에야 최종 내보내기 대상이 된다.

구현된 종료 반복 안정성 게이트는 P0와 P0_END를 L과 R에 대해 각각 독립적으로 비교한다.
200-500 Hz 중앙값 레벨 변동은 1.0 dB를 넘지 않아야 한다. 스탠드를 주변 지점들로
옮겼다가 손으로 되돌려 놓기 때문에, 20-500 Hz의 레벨 제거 응답 형상 RMSE에는 6.0 dB
라는 느슨한 대폭 변화 기준을 사용한다. P0_END는 중앙 영역의 별도 표본일 뿐, 마이크가
정확히 같은 자리에 놓였다는 증거는 아니다. 도달 타이밍은 이 검사로도 여전히 검증되지
않는다.

## REW에서 측정 결과 열기

승인된 모든 캡처는 `live-projects/<세션-id>/rew/` 아래에 캘리브레이션된 임펄스 응답의
모노 48 kHz IEEE-float WAV로도 저장된다. 세션 폴더 이름은 그 세션을 시작한 로컬
시각이다(`live-2026-07-30_19-35-22-000`, 끝의 세 자리는 같은 초에 두 세션을 시작했을
때만 올라간다). 이름이 시간순으로 정렬되므로 파일 목록이 곧 측정 이력이고, 캐시
복원이 "가장 최근 세션 우선"을 판단할 때도 이 순서를 쓴다. 파일 이름은 무엇을 언제 측정했는지를 나타낸다:

```text
L+Sub P0 2026-07-29 14-30-05.wav
L XO01 2026-07-29 14-22-31.wav
Sub XO01 2026-07-29 14-24-02.wav
L+Sub P0 filtered 2026-07-29 15-10-00.wav
```

`L`/`R`은 스피커 단독, `L+Sub`/`R+Sub`은 그 스피커와 서브우퍼가 함께 재생한 것,
`Sub`은 서브우퍼 단독이다. ` filtered`는 시험 필터를 적용한 상태에서 측정한 폐루프
캡처를 뜻한다. 2.0 프로젝트에서는 경로에 서브우퍼가 없으므로 기준 측정이 `L`/`R`이다.

REW의 **File → Import Impulse Response**로 불러오거나, REW 창에 끌어다 놓으면 된다.
REW는 임포트한 측정의 이름을 파일 이름에서 가져오므로 목록이 그대로 표시된다. REW에
들어간 뒤 REW의 **File → Save All Measurements**를 실행하면 진짜 `.mdat` 파일이
만들어진다.

앱이 직접 `.mdat`을 쓰지는 않는다. `.mdat`은 REW의 Java 직렬화 저장 포맷이고 제3자가
쓸 수 있는 공개된 규격이 없다. REW가 조용히 잘못 읽는 파일은 파일이 아예 없는 것보다
나쁘므로, 앱은 REW가 임포트 가능하다고 문서화한 포맷을 건네주고 저장 파일은 REW가 직접
쓰게 한다.

이 임펄스에는 마이크 캘리브레이션이 이미 적용되어 있다. 설계가 읽는 것과 같은 데이터이기
때문이다. 여기에 REW에서 UMIK 캘리브레이션 파일을 다시 불러오면 보정이 두 번 적용된다.

## 타이밍

제공되는 스테레오 스윕에는 측정 신호 앞뒤로 에너지가 더 낮은 이벤트가 들어 있다.
대응하는 두 이벤트가 모두 인식되면 라이브 어댑터는 그 소스/캡처 좌표를 피팅해
디컨볼루션용 클럭 비율을 추정한다. 그렇지 않으면 룸의 영향을 받은 스윕 내부 기울기
대신 비율 1을 사용한다. 이것으로 L/R 도달 시간의 신뢰도가 확보되지는 않는다. 가장 큰
임펄스 응답 샘플을 단지 표시 목적으로 0으로 옮기는 일은 절대 없으며, 현재 베타는 항상
좌/우 딜레이 보정을 비활성화한다. 마커 기반 디컨볼루션에서 저장되는 임펄스 응답은
마커로 매핑된 메인 경계를 기준으로 고정된 -100 ms 지점에서 시작한다. 이는 오른쪽
스피커 마커보다 먼저 도달하는 L 메인이나 서브의 도달을 보존하기 위한 것이며, 자동
타이밍 보정이 아니다.

## 캡처별 품질 게이트

- 캘리브레이션 파일이 존재하고, 파싱 가능하며, 분석 대역을 포함할 것.
- 입력 클리핑, CPAL 스트림 오류, 불완전한 캡처, 샘플 누락 의심이 없을 것.
- 스윕 이전 노이즈 플로어 증거와 최소 20 dB의 캡처 SNR이 있을 것.
- 재구성 적합도는 계속 표시되지만, 완전한 반복 마커 쌍이 독립적인 구간/클럭 증거를
  제공하는 경우에는 진단 정보로 취급된다. 마커 없는 대체 경로에서는 최소 12 dB
  적합도가 필요하다.
- 시간순으로 배열된 시작/종료 마커 쌍의 상관도가 각각 0.20 이상이거나, 대체 경로에서
  유일하게 식별된 전체 스윕의 상관도가 0.45 이상일 것. 아울러 심각한 샘플레이트
  불일치가 없을 것.
- 32,768 샘플 디컨볼루션 임펄스 응답을 위한 충분한 포스트롤이 있을 것. 이는
  16,320 탭 라이브 시험 FIR과는 구별되는 값이다. 번들 스윕은 메인 스윕이 끝난 지점과
  종료 마커가 끝나는 지점 사이에 58,080 샘플을 남겨 두며, 보존되는 꼬리는 종료 마커가
  시작되기도 전에 끝난다.

캡처 카드는 재구성 적합도를 SNR과 분리해 보여주고, 완전한 마커 쌍 캡처에서는 이를
진단 정보로 표시한다. 유한 창 선형 재구성이 모든 룸 감쇠나 스피커 왜곡을 모델링하지
못한다는 이유만으로, 그 외에는 깨끗한 측정을 배제하지는 않는다. 변경 불가능한 WAV는
결정적 재처리를 위해 계속 보관된다.

입력 클리핑과 -48 ~ -6 dBFS 메인 스윕 하드 리밋 범위는 자동 게이트이며, 권장 하한은
-30 dBFS로 유지된다. Sens Factor를 사용할 수 있으면 추정 SPL이 표시되지만 이는 허용
게이트가 아니다. 출력 클리핑, 인증된 절대 SPL, 음향적 채널 정체, 과도 신호 오염,
마이크 이동 의심, 반복 측정의 도달 타이밍은 사람이 확인해야 한다.

폐기된 캡처는 그 사유와 함께 프로젝트 이력에 남으며 모든 평균 계산에서 제외된다.

## 현재 사용 가능한 오프라인 Phase 3 리플레이

현재 측정 픽스처는 중앙 측정 위치 P0만 담고 있다. 후보 집합에는 메인 딜레이를
0.83 ms로 선언하고 크로스오버를 70, 80, 90 Hz로 바꿔 가며 측정한 L+sub와 R+sub 측정이
들어 있다. 서브 레벨과 극성은 후보 변수로 기록되지 않아 알 수 없는 상태로 남아 있다.
동일한 설정에서 반복 측정된 크로스오버 후보가 없으므로, 저장된 도달 메타데이터는
보관되지만 타이밍 반복성 점수로 승격되지는 않는다.

별도의 80 Hz 캡처에는 L 메인 단독, R 메인 단독, 서브 단독 A/B, 그리고 실제 측정된
L+sub와 R+sub 응답이 들어 있다. 이들은 복소합 일관성 진단을 뒷받침하지만, 측정되지
않은 극성 상태를 측정된 후보로 바꿔 주지는 않는다. 원본 L/R A/B 캡처와 서브 단독 A/B
캡처는 반복성 진단으로 보관되며, 동일 설정 크로스오버 반복 측정을 대신하지 않는다.

재현 가능한 리플레이를 위해 저장소 루트에서 실행하세요. `measurments/` 트리는 한
개발자의 개인 방 녹음이며 수백 메가바이트에 달해 공개 저장소에 **포함되지 않으므로**,
이 명령은 해당 파일이 로컬에 있는 환경에서만 실행된다. 이 파일들을 사용하는 회귀
테스트는 디렉터리가 없으면 실패하는 대신 `SKIPPED:` 줄을 출력한다:

```text
cargo run -p eqforbeginner-cli -- analyze-sub \
  --dataset measurments/derived/phase3-responses.json \
  --source-root measurments \
  --output <new-empty-output-directory>
```

CLI는 소스 해시가 바뀌었거나, 자동 레벨 정렬이 적용되었거나, 타임라인이 이동했거나,
그리드가 호환되지 않거나, 분리 경로 모델 게이트가 실패한 픽스처를 거부한다. 출력은
잠정적인 측정 후보 순위이며 완료된 통합이 아니다. `.mdat` 직접 변환은 개발용
마이그레이션 단계일 뿐이며, 향후 변환은 비공개 `.mdat` 파싱을 제품 기능으로 만들지
말고 문서화된 REW 5.40+ localhost API를 사용해야 한다.

## 현재 사용 가능한 오프라인 Phase 4 측정 응답 리플레이

Phase 4 픽스처 `measurments/derived/phase4-offline-measurements.json`은
`measurments/phase4`에 있는 48 kHz XO90 캡처 6개에서 유도된 것이다(이 역시 개발자
로컬 전용이다):

- `L_C90_D083.mdat`과 `R_C90_D083.mdat`: 중앙 P0의 L+sub/R+sub 기준 측정이자 필터
  설계의 권위 있는 응답;
- `L_M90.mdat`과 `R_M90.mdat`: 메인 단독 분리 경로 증거;
- `S90_A.mdat`과 `S90_B.mdat`: 반복 측정된 서브 단독 분리 경로 증거.

인정된 하드웨어 상태는 명시적으로 가정이다. 크로스오버 90 Hz, 메인 딜레이 0.83 ms이며,
이 베타 리플레이에서는 그 딜레이를 최적값으로 취급한다. 극성, 서브 레벨, 재생 볼륨,
마이크 게인은 변경되지 않았다고 선언되었지만 그 값은 기록되지 않았다. 이 가정들은
`user-declared`와 `verified=false`로 보관된다. 서브 단독 경고는 계속 표시되며, 해당
캡처들은 절대 결합 필터 설계 경로를 대신하지 않는다.

오프라인 리플레이는 새로 만들었거나 비어 있는 대상 디렉터리로 실행하세요. 위와
마찬가지로 이 소스 캡처들은 개발자 로컬 전용이며 공개 저장소에 포함되지 않는다:

```text
cargo run -p eqforbeginner-cli -- verify-48k-offline \
  --dataset measurments/derived/phase4-offline-measurements.json \
  --source-root measurments/phase4 \
  --output <new-empty-output-directory>
```

FIR 설계 전에 CLI는 소스 6개의 해시와 크기, 정확한 응답 역할과 공통 48 kHz 그리드,
UMIK 캘리브레이션 정체와 커버리지, 보존된 음향 기준 메타데이터, 변경되지 않은
SPL/타임라인 정책, 원본 L/R 결합 임펄스 응답 타임라인을 검증한다. 또한 각 메인 단독 +
서브 A/B 복소 예측이 45-180 Hz 구간에서 대응하는 측정된 결합 응답과 1.0 dB RMSE 이내로
일치할 것을 요구한다.

저장된 REW 결합 크기 응답이 설계의 권위이다. 원본 결합 임펄스 응답은 유한 시간 영역
진단 목적으로만 컨볼루션되며 원래의 `startTime`을 유지한다. 그 최댓값 샘플은
클리핑이나 재생 트루 피크, 헤드룸의 증거가 아니다. 출력은 48 kHz, 16,384 탭 스테레오
float32 시험 WAV와 설계/예측 리포트이다. 이 출력에는 항상 `predicted-only-measured`
라벨이 붙는다. 이 명령은 의도적으로 Roon ZIP을 만들지 않는다.

### 오프라인 픽스처에 없는 증거

시험 FIR을 적용한 뒤에 측정한 자료가 없다. 또한 P0만 있고, 각 결합 응답의 동일 설정
반복 측정도 없으며, 실제 경로의 클리핑·샘플 누락·채널 매핑 검사도 없다. 따라서 이 CLI
출력은 항상 다음을 유지한다:

- `hardware_verification`은 `unverified`로, `closed_loop_passed`는 null로 남는다;
- 최종 Roon 내보내기는 계속 대상이 될 수 없다;
- 권장 헤드룸은 추측한 상수를 쓰는 대신 사용 불가 상태로 남는다;
- "검증됨(verified)", "보정 완료(correction complete)" 및 이에 준하는 UI 문구는
  금지된다.

라이브 개발자 베타 패널은 이제 기준, 시험, 시험 이후 P0 측정에 대해 별도의 증거 경로를
구현하고 있다. 이를 실행해도 저장소에 커밋된 이 오프라인 픽스처가 변경되거나 승격되지는
않는다.

## 현재 사용 가능한 오프라인 Phase 6 개발자 프리뷰

네이티브 레이트 엔진은 새로운 음향 증거를 주장하지 않고도 시험해 볼 수 있다. 반드시
새로 만든 Phase 4 출력에서만 실행하세요. 예전의 픽스처 전용 데스크톱 진단 패널은 제품
UI에 마운트되어 있지 않다. 아래의 `examples/` 트리는 개발자 로컬의 Phase 4 출력
디렉터리이며 공개 저장소에 포함되지 않으므로, 직접 실행한 `verify-48k-offline`의 출력
디렉터리로 바꿔 사용하세요:

```text
cargo run -p eqforbeginner-cli -- prepare-phase6-beta \
  --phase4-project examples/phase4-offline-measured/project.json \
  --design-csv examples/phase4-offline-measured/filter-design.csv \
  --phase4-wav examples/phase4-offline-measured/filter/EQforBeginner_48000_Phase4_Trial.wav \
  --output <new-empty-output-directory>
```

이 명령은 레거시 Phase 4 설계/소스 바인딩을 검증하고, 6개 네이티브 샘플레이트를 다시
설계하며, 확인 가능한 엔지니어링용 WAV를 기록한다. ZIP은 의도적으로 만들지 않는다.
입력이 아직 예측 전용이고, FIR을 적용한 캡처가 없으며, 트루 피크 헤드룸 결과가 없기
때문이다. 이 프리뷰 WAV를 손으로 만든 Roon ZIP에 복사해 넣지 마세요.

패키지 파서 개발용으로만 쓰이는 `generate-phase6-reference`는 명백히 합성된 6개 레이트
구조 ZIP을 만든다. 이는 청취용 필터가 아니며, 절대 이름을 바꾸거나 측정된 보정인 것처럼
제시하지 않는다.

### 구현된 minimum-phase 최초 사용 경로

이 문서 맨 위의 실제 측정 개발자 베타 단계를 사용하세요. Phase 4의 48 kHz
minimum-phase 시험 필터에서 시작한다. 어댑터는 원본 및 캘리브레이션된 스냅샷을
보존하고, 승인된 시험 이후 P0 L/R을 요구하며, 그 뒤에야 네이티브 48 kHz 구성원을 응답
바인딩하고 신호/FIR 한계 헤드룸을 계산한 다음 최종 6개 레이트 ZIP을 요청한다.
minimum-phase 전용 패키지가 유일한 설계 경로이자 유일한 라이브 출력이다.

## 라이브 단일 서브 최적화기의 경계

구현된 라이브 경로는 변경 불가능한 크로스오버 계획을 기록하고, 승인된 분리 캡처를 모두
보관하며, 제한된 딜레이 그리드와 두 극성을 탐색하고, 순위가 매겨진 JSON 리포트를
기록하며, Raw 캡처를 활성화하기 전에 정확한 권장값이 실제 하드웨어에서 사용자 확인을
받도록 요구한다. 새로 승인된 분리 캡처가 생기면 기존 순위와 그 하위 설계가 무효가 된다.
실패한 재시도는 원본 WAV/JSON 제외 기록으로 남지만, 이전에 승인된 값을 밀어내지는
않는다.

동일한 캘리브레이션과 L/R WAV를 다시 가져오고 동일한 2.1 탐색 계획을 저장한 뒤에는,
이미 통과한 캡처를 반복하는 대신 **승인된 측정 캐시 복원**(Restore accepted
measurement cache)을 사용할 수 있다. 표시되는 소스 프로젝트 ID를 확인하세요. 캐시는
호환되는 프로젝트를 최신순으로 훑어 각 측정 종류/측정 위치/채널 칸마다 가장 최근의
승인된 값을 복원한다. 따라서 더 최근의 불완전한 세션에서 비어 있는 칸을 예전에 통과한
값이 채울 수 있다. 정확한 해시, 마이크 채널, 크로스오버 계획, 딜레이, 극성, 서브 레벨은
여전히 일치해야 하며, 그중 하나라도 의도적으로 바꾸면 복원되는 측정이 없다.

이는 여전히 P0만을 이용한 예측이다. 하드웨어 성능 탐지, 0/180도 이외의 위상 조절, 서브
레벨 탐색, 다중 위치 후보 점수화, 명시적인 예측 대 결합 음향 모델 게이트는 앞으로의
과제로 남아 있다. 이어서 요구되는 Raw P0 쌍은 실제 결합 경로가 측정되었음을
입증하지만, 베타는 아직 그 쌍을 분리 캡처 기반 복소합 예측과 수치적으로 비교하지
않는다. 따라서 UI는 "예측된 권장값(predicted recommendation)"이라고 표시하며, 절대
"서브우퍼 통합 완료(subwoofer integration complete)"라고 표시하지 않는다.
